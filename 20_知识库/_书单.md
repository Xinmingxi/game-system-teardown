## 提取规则

- 一本书不整本抄，**只提取拆解时会用到的概念**
- 一个概念一张卡，进 `20_知识库\知识卡_【概念名】.docx`
- 卡片模板见 `00_规范\03_知识模板.md` 模板 A

## 阅读顺序（按求职优先级）

不是「读多少本」，是「每个阶段读一本能马上用在拆解里的」。

### 第一梯队 · 先建立语言（1~2 周）

| 书 | 为什么是它 |
| --- | --- |
| MDA 论文（Hunicke / LeBlanc / Zubek） | 六页，免费。机制 → 动态 → 体验这条线，是系统策划的入门语法 |
| 系统之美（Meadows） | 计算机专业其实已经懂一半（存量/流量 ≈ 状态/转移），读它是把直觉换成能说出口的词 |
| 游戏设计艺术（Schell） | **不要通读**。当词典用：拆解卡住时翻对应的透镜 |

### 第二梯队 · 拆解时配套读（边拆边读）

| 书 | 为什么是它 |
| --- | --- |
| 游戏机制（Adams & Dormans） | 讲机制经济与正负反馈，和循环图直接对得上 |
| 体验引擎（Sylvester） | 情绪是体验单位；解释「为什么这个数值一调手感就变了」 |
| 快乐之道（Koster） | 乐趣 = 学习；用来判断一个系统什么时候会被玩腻 |

### 第三梯队 · 求职前补实务

| 书 | 为什么是它 |
| --- | --- |
| 平衡掌控者（国内作者，数值战斗方向） | 国内实务，讲具体公式与成长曲线。买之前先确认版本 |
| 上瘾（Eyal） | 留存四段式；拆商业化系统时用 |
| 游戏设计梦工厂（Fullerton） | 练流程：原型 → 测试 → 迭代。面试常问「你怎么验证设计」 |

### 暂时别读

叙事、关卡、美术类，成功学式的运营书，以及游戏通史。现在读它们不是准备，是**延迟**。

## 读书规则

- 一本配一次拆解：读完一章，就在 20_知识库 落一张 T- 卡
- 不写摘抄，写「这个视角让我看懂了哪个游戏」
- 一本书只允许贡献 2~3 张卡，剩下的等下次拆解再用
