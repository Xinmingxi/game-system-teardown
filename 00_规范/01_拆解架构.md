# 系统拆解架构

> 拆解不是描述系统，是**还原决策**：设计者面对什么约束、做了哪些取舍、这些取舍落到玩家身上变成了什么体验。

## 一、四层结构

| 层 | 问的问题 | 产出 | 常见错误 |
| --- | --- | --- | --- |
| L1 体验层 | 它想让玩家感觉到什么 | 一句话体验目标 + 2~3 个情绪词 | 写成「玩法好玩」 |
| L2 结构层 | 由哪些模块和循环组成 | 循环图 + 模块清单 | 写成功能罗列 |
| L3 数值层 | 关键参数是多少 | 3~5 个参数与函数形状 | 抄一堆数值表 |
| L4 表现层 | 玩家看到、听到什么 | UI 与反馈要点 | 在这层纠结美术 |

**读的顺序是从内到外**：先抓 L3 的硬数据，再往上解释 L2，最后才说 L1。

**写的顺序是从外到内**：读者要先知道目标，才知道你在解释什么。

两件事反过来做，文档就会变成「功能说明书」——面试官一眼就能看出来。

## 二、六个必答问题

| # | 问题 | 理论锚点 | 出处 |
| --- | --- | --- | --- |
| 1 | 它想制造什么体验 | MDA 的美学层，8 种感受 | Hunicke / LeBlanc / Zubek《MDA》 |
| 2 | 玩家为什么持续投入 | 自主 · 胜任 · 关联 | Deci & Ryan 自我决定理论 |
| 3 | 动力从哪来、卡在哪 | 存量 / 流量 / 增强回路 / 调节回路 / 延迟 | Meadows《系统之美》 |
| 4 | 玩家在学什么 | 乐趣 = 学习模式 | Koster《快乐之道》 |
| 5 | 节奏为什么这样排 | 期待与落差 | Sylvester《体验引擎》 |
| 6 | 它被什么约束 | 机制 / 故事 / 美学 / 技术 四元素 | Schell《游戏设计艺术》 |

**MDA 的 8 种美学感受**：感官、幻想、叙事、挑战、社交、发现、表达、消遣。

用法：拆解开头就圈出这个系统主打的那 2~3 个，后面每一节的判断都要回看它们。脱离了目标的「好」和「烂」都是空话。

## 三、循环图怎么画

- 节点 = **存量**（钱、等级、体力、角色数、天数）
- 箭头 = **流量**（产出、消耗、转换）

四种基本回路：

| 回路 | 形状 | 例子 | 拆解时要问 |
| --- | --- | --- | --- |
| 增强（正反馈） | 越……越…… | 钱多 → 兵多 → 抢更多钱 | 加速会不会失控？天花板在哪 |
| 调节（负反馈） | 越……越难…… | 等级越高，经验需求越大 | 是平滑的坡还是硬墙 |
| 转换 | A 换成 B | 时间换资源、资源换战力 | 汇率谁定的，为什么是这个值 |
| 触发 | 事件开门 | 到 30 级解锁副本 | 这是拦人还是引导 |

必答一句：**这个循环转一圈要多久**——秒、小时、天还是周。时间尺度直接决定了它服务哪一类玩家。

## 四、参数还原五法

1. **端点法**：从 0 和极大值倒推函数形状
2. **锚点法**：官方公示、攻略数据、自己实测的样本
3. **单调性法**：先判断是线性、边际递减还是分段，再拟合
4. **隐藏项排查**：每日上限、冷却、概率权重、软保底
5. **行为反推**：用玩家的实际行为（大众停在第几关）反推设计意图

参数不必精确，**形状对了就有价值**。写「大概每级 +8%，30 级后转平」比写「7.83%」更有用。

## 五、反事实推演三问

1. 改一个参数 → 玩家行为怎么变
2. 砍掉一个模块 → 哪一环先崩
3. 搬到另一个品类 → 哪里不成立

只做第 1 问也够，但**必须做一次**。这是全篇最值钱的一段，也是绝大多数人跳过的。

## 六、崩坏预演：五种死法

| 崩溃类型 | 机制 | 早期信号 |
| --- | --- | --- |
| 通胀 | 产出长期大于回收，货币贬值 | 物价飞涨、突然加大回收口 |
| 膨胀 | 数值上限被反复抬高 | 上赛季的装备变废纸 |
| 躺平 | 目标太远，玩家放弃追赶 | 中后期时长断崖 |
| 付费失效 | 付费点是唯一出口 | 免费玩家无路可走 |
| 社交死亡 | 社交没有强制互赖 | 公会活跃度跌、组队无人 |

每份拆解挑一个最可能的，把机制讲清楚。不用全写。

## 八、拆解 SOP（七步）

1. **选品**：从 04_进度索引.md 的起步清单挑，一个品类先拆一个
2. **备料**：确认版本号与平台，收官方公告、更新日志、社区讨论
3. **采集**：自己玩 + 录屏 + 截图，记关键节点（第 1 小时 / 第 3 天 / 第 7 天 / 第 30 天）
4. **复原**：画循环图，列模块，用五法抓参数
5. **推演**：反事实 + 崩坏预演
6. **写作**：按 02_拆解模板.md 逐节填
7. **沉淀**：把用到的理论抽成知识卡放进 20_知识库，回索引登记

## 九、产出物与归档

每份拆解出两件，同目录同名：

- `游戏名_系统名_拆解.md` —— 工作稿，随时改
- `游戏名_系统名_拆解.docx` —— 正式稿，交给人看的就是它

转换命令：

```
python 工具/md2docx.py 01_MMORPG\魔兽世界_经济_拆解.md 01_MMORPG\魔兽世界_经济_拆解.docx
```

## 十、失败模式自检

| 症状 | 说明 |
| --- | --- |
| 全文没有「因为」，只有「是」 | 你在复述 |
| 参数列了一大堆 | 你没找到那关键的三个 |
| 没有崩坏预演 | 你没想过它怎么死 |
| 结论和开头的目标对不上 | 你在套模板 |
| 换个游戏名也读得通 | 你什么都没拆 |
